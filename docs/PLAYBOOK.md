## 二、四人推荐分工模型

新手队最容易踩的坑是“4 个人一起改同一坨代码”或“所有人都写代码、最后半小时才发现没人做 PPT”。建议按以下 4 个角色认领（如果某方向人手强弱不同，可以一人兼主副角）：

1. **统筹 / 产品 + 集成负责人（队长）**
   - 盯住时间轴，果断**砍需求**（凡是 3 小时做不完的非核心功能，一律砍掉或 Mock）。
   - 维护接口契约文档（输入什么、返回什么）、协调代码合并与解决冲突。
   - 负责核对官方提交清单并完成最终提交。
2. **前端 / 交互体验负责人**
   - 负责演示界面与交互流程（评委 80% 的第一印象来自你展示出来的界面）。
   - 优先使用现成组件库/模板和 AI 辅助快速出图，先保证核心展示页好看、顺滑。
3. **后端 / AI / 核心逻辑负责人**
   - 负责把核心功能（大模型调用、算法、数据处理、API 接口）稳定跑通。
   - 第一时间给前端提供可调通的接口或 Mock 数据，不卡住前端进度。
4. **全栈补位 + Demo / PPT / 路演主讲**
   - Day 1 协助写独立子模块、造高质量演示测试数据。
   - Day 2 上午起接管 [路演模板](../pitch/PITCH_TEMPLATE.md)、制作 PPT、录制兜底 Demo 视频、写评委 Q&A 预案并组织彩排。

## 三、Git & GitHub 四人极简协作规范

### 1. 为什么必须建 GitHub 仓库？
- **并行不打架**：4 个人各自在本地写代码，通过 GitHub 同步，避免靠微信传 zip 把队友代码覆盖。
- **随时能回滚**：Demo 前改崩了代码，一行命令退回上一个能跑的版本。
- **提交必需品**：绝大多数黑客松都要求提交 GitHub 仓库链接，规范的 README 和提交记录本身就是加分项。

### 2. 目录隔离约定（减少冲突的核心技巧）
定好技术栈后，建议把仓库按模块拆成独立目录，**尽量每人主改自己的目录**：

```text
xpoint/
├── frontend/   # 前端代码（成员 B 主负责）
├── backend/    # 后端 / AI 逻辑（成员 C 主负责）
├── docs/       # 赛程、计划书、接口文档（成员 A 主负责）
└── pitch/      # PPT、演示视频链接、讲稿（成员 D 主负责）
```

### 3. 分支与合并规则（轻量化，适合 48 小时冲刺）
- `main` 分支永远保持**“能跑起来”**的状态，不要直接把半成品强推到 `main`。
- 每个人从 `main` 切自己的分支开发，例如：
  - `feat/frontend`
  - `feat/backend`
  - `feat/pitch`
- **高频小步合并**：每完成一个小功能（每 2–3 小时）就合回一次 `main`，千万别攒到第二天上午一次性合并（否则合并冲突能把你们拖垮）。
- **合并前双保险**：合并前先拉取最新 `main` 在本地跑一遍，确认没报错再推。

### 4. 新手最常用 6 条 Git 命令速查

```bash
# 1. 第一次克隆仓库到本地
git clone <仓库地址>
cd xpoint

# 2. 切出自己的开发分支（首次）
git checkout -b feat/你的模块名

# 3. 写完一个小功能后提交到本地
git status
git add .
git commit -m "feat: 完成核心页面布局"

# 4. 推送到 GitHub
git push -u origin feat/你的模块名

# 5. 同步队友合进 main 的最新代码（经常执行！）
git checkout main
git pull origin main
git checkout feat/你的模块名
git merge main

# 6. 需要合回 main 时：在 GitHub 上提 Pull Request 并 Merge（或在本地确认无冲突后合并）
```

> **安全红线**：API Key、数据库密码一律写在本地 `.env` 里（已被 `.gitignore` 忽略），把变量名写进 `.env.example` 共享给队友。**绝不要把真实密钥写死在代码里推到 GitHub！**

## 四、第一次参加黑客松的 6 条避坑铁律

1. **演示驱动（Demo Driven）**：登录注册、找回密码、复杂权限管理、后台 CRUD 这些评委不会看的功能，**全部砍掉或跳过**，直接一打开就进入最精彩的核心场景。
2. **先做“丑但能跑”的闭环**：Day 1 傍晚一定要跑通端到端主流程，不要前端画了一天静态页、后端写了一天接口，结果第二天中午发现接不上。
3. **一定录兜底视频**：现场 Wi-Fi 断网、API 限流、笔记本连不上投影仪在黑客松里太常见了。11/22 中午提前录好 1–2 分钟流畅演示视频，真出意外立刻播视频解说。
4. **11:00 强制封板**：11/22 上午 11:00 以后禁止加新特性、禁止大重构。留足 2 小时修致命 Bug、补 README、提交表单和练路演。
5. **善用现成轮子和 AI**：黑客松允许用的开源组件、UI 模板、大模型 API 尽管用，把时间花在**创意本身和核心体验**上，不要手搓底层轮子。
6. **把路演当成一半的分数**：做得很强但讲不明白会非常吃亏。提前对照 [PITCH_TEMPLATE.md](../pitch/PITCH_TEMPLATE.md) 把故事线理顺并计时演练。
