## 2. 比赛规则记录（已核对 Devpost 官方全文）

> 官方页面：<https://cpx2026.devpost.com/>（[Rules](https://cpx2026.devpost.com/rules) / [Resources](https://cpx2026.devpost.com/resources)）｜现场原图：[cpx-2026-tracks-rules.jpg](cpx-2026-tracks-rules.jpg)

- **已锁定赛道**：**Track 2: Reverse UX Challenge（逆向 UX 挑战赛）**
  - **核心主题**：**Design an App That Users Hate, but Still Have to Use（设计一款用户讨厌、但又不得不用的 App）**
  - **核心要求**：
    1. 至少包含 **3 处刻意设置、令人抓狂的交互设计机制（deliberately frustrating UX mechanisms）**。
    2. **Bad UX ≠ Bad Coding**：代码质量、交互流畅度与视觉完成度必须过硬，不能做成“真有 Bug 的烂软件”。
    3. **功能真实可用**：用户**至少有一种途径**能走完完整任务流程，并产出**可见的执行结果**。
    4. **阐释设计逻辑**：清楚讲明每一处“反人类交互”背后的 UX 原理 / 暗黑模式 / 心理学与产品设计逻辑。
  - *(备查：Track 1 为 Apple Human-Centered Care，强制要求 Swift/SwiftUI/Core ML，我方不选)*
- **评审方式与权重（Devpost 官方逐项细则）**：
  - **评审形式**：线下 Expo 展台巡回评审，评委组到每桌进行 **3–5 分钟**的现场演示 + 问答（评委包含西浦 AIAT 副院长/教授、SCS 导师、Synopsys、Dify 及 SIA/DKU 学生主席，注重调研证据、技术完成度与严谨的设计逻辑）。
  - **五项评分权重与原文侧重点**：
    - **Technical Completion（技术完成度）：25%** — 原型质量与可运行状态、技术难度、实现健壮性、48 小时内的实际交付深度（最高权重！）
    - **User Need & Problem Understanding（用户需求与问题理解）：20%** — 明确目标用户与真实痛点，**必须基于真实用户调研与证据排优先级，而非拍脑袋假设**（定题后建议现场访谈/问卷 10–20 位同学留证！）
    - **Creativity & Innovation（创意与创新）：20%** — 思路原创性，超越显而易见的答案并提供意料之外的价值
    - **Design & User Experience（设计与用户体验）：20%** — 可用性、交互与视觉打磨、**包容性与无障碍（inclusiveness & accessibility）**（策略：只在 3+ 处刻意逆向机制上制造“可控抓狂”，其余字号/对比度/键盘可达性/解剖面板保持高水准无障碍设计）
    - **Presentation & Communication（展示与表达）：15%** — 3–5 分钟展台演示清晰度、讲故事能力、问答表现与团队协作
- **构建与提交强制清单（Devpost 官方逐条核对，缺一可能判为不完整！）**：
  1. **Devpost 全员挂名**：4 名成员必须全部加入 Devpost 提交页的 `Manage team`。
  2. **项目页信息与完整描述**：项目标题、简短摘要、完整描述（必须写清：问题、具体目标用户、体现“有取舍的功能优先级”的解决方案、原型核心功能、**每位成员的分工**、以及开源库/API/AI 工具披露）。
  3. **两个可公开访问的链接（截止前务必实测！）**：
     - **可访问的在线 Demo / 原型链接**（不能只跑在 `localhost`，需部署公网链接，如 Vercel / Netlify / Cloudflare Pages）
     - **公开源代码仓库链接**，且必须采用 **Apache License 2.0**（根目录已预置 `LICENSE`）
  4. **项目海报三件套与精确提交位置（缺一判不完整！）**：
     - 海报必须概括：**用户与任务场景 + 核心功能或反向设计机制 + 关键设计启示**
