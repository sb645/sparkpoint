## 2. 比赛规则记录（已核对 Devpost 官方全文）

> 官方页面：<https://cpx2026.devpost.com/>（[Rules](https://cpx2026.devpost.com/rules) / [Resources](https://cpx2026.devpost.com/resources)）｜现场原图：[cpx-2026-tracks-rules.jpg](cpx-2026-tracks-rules.jpg)

- **已锁定赛道**：**Track 2: Reverse UX Challenge（逆向 UX 挑战赛）**
  - **核心主题**：**Design an App That Users Hate, but Still Have to Use（设计一款用户讨厌、但又不得不用的 App）**
  - **核心要求**：
    1. 至少包含 **3 处刻意设置、令人抓狂的交互设计机制（deliberately frustrating UX mechanisms）**。
    2. **Bad UX ≠ Bad Coding**：代码质量、交互流畅度与视觉完成度必须过硬，不能做成“真有 Bug 的烂软件”。
    3. **功能真实可用**：用户**至少有一种途径**能走完完整任务流程，并产出**可见的执行结果**。
    4. **阐释设计逻辑**：清楚讲明每一处“反人类交互”背后的 UX 原理 / 暗黑模式 / 心理学与产品设计逻辑。
  - *(备查：Track 1 为 Apple Human-Centered Care，强制要求 Swift/SwiftUI/Core ML，我方不选)*
- **评审方式与权重（Devpost Rules 官方标准）**：
  - **评审形式**：线下 Expo 展台巡回评审，评委组到每桌进行 **3–5 分钟**的现场演示 + 问答（极适合让评委亲手体验几秒“被折磨”！）。
  - **五项评分权重**：
    - **Technical Completion（技术完成度）：25%**（权重最高！）
    - **User Need & Problem Understanding（用户需求与问题理解）：20%**
    - **Creativity & Innovation（创意与创新）：20%**
    - **Design & User Experience（设计与用户体验）：20%**
    - **Presentation & Communication（展示与表达）：15%**
- **强制提交与合规清单（缺一可能判为不完整！）**：
  1. **Devpost 全员挂名**：4 名成员必须全部加入 Devpost 提交页的 `Manage team`。
  2. **公开代码仓库 + Apache-2.0 协议**：必须提交公开 GitHub 仓库链接，且仓库必须采用 **Apache License 2.0**（根目录已预置 `LICENSE`）；必须在提交页/README 中**清晰披露**使用的开源库、第三方 API 及 AI 辅助开发工具。
  3. **可运行原型（Working Prototype）**：能现场演示完整任务流程并输出可见结果。
  4. **项目海报三件套（AMD 生成与存证，缺一不可！）**：
     - ① **最终项目海报**（基于 AMD 图像生成 API 原图，**仅允许轻度编辑**：调色、锐化、裁剪、排版与叠加文字；**严禁用其他生图模型重绘或替换核心主视觉**）
     - ② **AMD API 返回的未编辑原图（Raw Image）**
     - ③ **生成证明截图**：`AMD Creative Factory → Image → My work → Gallery` 页面截图
- **官方免费赞助资源（在参赛者微信群领取，Key 严禁入库只放本地 `.env`）**：
  - **AIHubMix**：每队发放的多模型聚合 API Key
  - **Dify**：官方云端工作区 + 模板 + 现场导师
  - **AMD Creative Factory**：图像生成 API 访问链接与 Key（海报生成专用）
