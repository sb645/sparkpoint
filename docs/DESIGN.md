# 视觉与界面规范

> 状态：v1，2026-11-21 成员 1 定稿。所有界面（含成员 3 的 `frontend/deep/` 模块）按本文的变量和规则做。改动先改本文。
> 变量都在 [`frontend/styles.css`](../frontend/styles.css) 开头的 `:root`，**深化模块直接用这些 CSS 变量，不要自己写颜色和字体**。

## 1. 简报

- **用户**：展台评委（教授、企业导师、学生主席）和路过的同学。在笔记本上被演示员带着操作，偶尔用手机扫码自己试。
- **场景**：嘈杂的展台，3–5 分钟。评委要在几秒内看懂"我正在和昨晚的自己签合同"。
- **气质**：一本正经、官僚、像真的票据；越认真越好笑；但字清楚、不刺眼。
- **参考**：银行支票和票据的防伪底纹纸、复写纸填写的手写字、公司合同专用章、合同里的"第一条、第二条"。
- **禁忌**：紫色渐变、玻璃拟态、emoji、千篇一律的圆角卡片和阴影、霓虹暗色。**不加载任何网络字体**（展台网络不稳，境内也连不上 Google Fonts）。

## 2. 核心设计决定

**印刷字和手写字分开**：合同里系统印好的条文用宋体、墨色；用户自己填的内容（时间、理由、借口）一律用楷体、复写紫。早上修订页里那句"你昨晚说"仍是复写紫的楷体，一眼就认得出是"你自己写的"。这是整个产品唯一的视觉主线。

**唯一一处主动动效是盖章**：签约时公司合同专用章盖下去。别的地方只有响应用户操作的反馈，不加入场动画。尊重 `prefers-reduced-motion`。

**桌面颜色表示时间**：纸张始终是同一张票据纸，纸外的桌面在签约时是深夜蓝，响铃后是清晨灰蓝，完成后是白天。评委不看文字也知道现在是晚上还是早上。

## 3. 变量

| 名字 | 值 | 用途 |
| --- | --- | --- |
| `--paper` | `#EEF2EC` | 票据纸（带淡绿的灰，不是米黄） |
| `--guilloche` | `#CFDCD3` | 防伪底纹、细分隔线 |
| `--ink` | `#232A26` | 印刷字 |
| `--ink-soft` | `#55605A` | 次要说明（对纸张对比度 ≥ 5.5:1） |
| `--carbon` | `#3B3486` | 用户手写内容、主操作按钮 |
| `--seal` | `#C0272D` | 公章、错误提示、响铃标记 |
| `--desk-night` / `--desk-dawn` / `--desk-day` | `#18233A` / `#5E6F86` / `#C9D2CC` | 纸外桌面 |

字体：

| 角色 | 字体栈 |
| --- | --- |
| 印刷字（标题、条文、数字） | `--font-print`：Songti SC、STSong、Noto Serif CJK SC、SimSun |
| 用户手写内容 | `--font-hand`：Kaiti SC、STKaiti、KaiTi |
| 按钮、表单、小字 | `--font-ui`：PingFang SC、Hiragino Sans GB、Microsoft YaHei、system-ui |

字号：16 / 18 / 22 / 30 / 56（大时间）。正文行高 1.7，条文最长 36 个汉字一行。数字统一 `tabular-nums`。

## 4. 版式

```
桌面（随时间变色）
┌ 顶栏：公司名                  查看设计逻辑 ▢  演示静音 ▢  重新开始 ┐
        ┌──────── 票据纸，最宽 40rem，居中 ────────┐
        │ 起床合同                    合同编号 …   │
        │ 甲方 昨晚的我        乙方 今早的我        │
        │ ─────────────────────────────────────── │
        │ 第一条 …（手写内容用复写紫楷体）           │
        │ 第二条 …                                 │
        │                               （公章）    │
        └──────────────────────────────────────────┘
        （响铃阶段）纸下方固定：不可抗力
```

- 内容一律左对齐；只有大时间和公章居中。
- "第一条、第二条"只用于真正的合同条款，不拿来装饰别的列表。
- 手机上纸张贴满宽度，边距 16px。

## 5. 组件

- **主按钮**：复写紫底、纸色字、2px 圆角（票据上的方正感）。**次按钮**：透明底、墨色 1px 边框。**文字按钮**：带下划线。最小点击区域 44×44。
- **焦点**：所有可操作元素 3px 复写紫外框，偏移 2px，不能去掉。
- **错误**：印泥红文字 + 左侧红竖线，写清楚怎么改，不道歉。由 `aria-live` 区域播报。
- **故意的"次要入口"**（验收页「完成验收并关闭」）：做成文字按钮，看起来不起眼，但字号 ≥ 16px、对比度达标、键盘可达。抓狂来自位置和层级，不来自看不清。
- **设计逻辑卡片**：开关打开后插在机制下方，墨色虚线框，三行：故意违反的原则 / 为什么 / 怎么通关。

## 6. 给成员 3 的深化模块

`mountXxx(container, …)` 拿到的 `container` 已经在纸面上，宽度跟随纸张。模块内：

- 颜色、字体只用上面的变量；按钮直接用 class `btn btn-primary` / `btn btn-secondary`。
- 早上的模糊晃动效果只作用在模块自己的测试区域，不要改 `body` 或纸张。
- 必须支持键盘（空格或回车代替点击）和 `prefers-reduced-motion`（关闭晃动，只保留模糊）。
