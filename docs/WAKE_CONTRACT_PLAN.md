# 《昨晚的我有限公司》开发方案与四人分工

CrossPointX 2026 · Track 2 Reverse UX Challenge · 2026 年 11 月 21–22 日，以下时间均为北京时间。成员按仓库已有角色 A–D 认领。

## 交付目标

评委先以“昨晚的我”签下一份起床合同，再以“今早的我”尝试反悔。睡前愿意授权，是因为自己想准时赴约。早上想多睡五分钟时，产品拿着本人签的条款要求履约。交付一条可以独立走完的网页流程、一个可公开访问的演示链接，以及通过 Dify 的 AMD 插件生成并用真实界面截图完善的项目海报。

**第一项验收**：两个人签不同合同，第二天点同一个「再睡五分钟」。宽松合同立即获准，严格合同必须引用昨晚的原话并修改约定。只更换文案、两条路径实际表现相同，视为这项未完成。

## 体验与通过条件

| 步骤 | 评委的操作 | 系统行为与可见结果 |
| --- | --- | --- |
| 昨晚签约 | 设起床时间、填一句理由（可用“八点去接室友”），二选一签约 | 同屏展示「允许直接贪睡一次」「改时间必须修订合同」的差别。签后保留原时间、原话、原条款 |
| 模拟早晨 | 点「进入第二天」 | 播放轻响铃声，出现「关闭闹钟」「再睡五分钟」，固定位置提供演示静音 |
| 选择贪睡 | 两种合同都点「再睡五分钟」 | 宽松首次直接暂停响铃；严格合同与宽松的第二次贪睡都进入修订。修订页展示原理由，用户将时间改到当前约定时间加五分钟后确认。批准即停响，显示新时间；点「模拟五分钟后」才再次响铃 |
| 申请关闭 | 任一响铃页点「关闭闹钟」 | 显示“已收到关闭申请”，进入一道滑块算术。当前值可见、可用方向键微调，答案正确后进入验收；答错留在本题 |
| 完成验收 | 阅读两个含义相近的选项，选择「完成验收并关闭」 | 停响并生成履约报告。选择「继续监督」则回到验收说明，保留已通过的认证；用户可以随时选择完成 |
| 查看回执 | 对照昨晚与今早 | 显示原时间、最终时间、贪睡次数、清醒任务耗时、手续耗时。演示员能一键重置并切换合同再来一轮 |

**三处必做的反向 UX**：关闭按钮仅登记意向，破坏按钮标签带来的完成预期；用 0–100 的滑块提交精确算术答案，增加操作成本；通过认证后仍须从视觉次要但清晰可读的入口完成验收，增加退出成本。严格合同的修订手续另外体现过去的授权如何约束现在的选择。直接关闭路径也能体验全部三处。

## 四人认领表

| 人员与目录 | 先交付，让队友可以开工 | 主体开发与协作 | 交付给谁、如何验收 |
| --- | --- | --- | --- |
| **A 统筹与集成** · `docs/`，负责集成分支 | 锁定两份示例合同、屏幕顺序、下方事件契约，建任务看板；与 B 确认部署入口 | 搭可访问的静态预览；审核 B/C 分支并集成；复查时间跨日、静音、重置和外链；与 D 核对提交材料 | 给全队一个稳定网址和可本地启动的版本。用全新浏览器会话分别跑两份合同，通过后标记演示版本 |
| **B 前端与交互** · `frontend/` | 先做签约、响铃、回执三屏，以 C 的固定示例状态展示两条分支 | 完成合同修订、滑块、验收界面，接 C 的事件和状态；负责音频启停、静音和页面内焦点；修复笔记本与手机布局 | 交 A 可操作完整页面，交 D 截图位置。触屏与键盘都能完成严格路线，错误可改，静音能继续操作 |
| **C 合同规则与统计** · `backend/` | 导出纯 JavaScript 规则模块和两份合同样例，先让 B 能调用「签约→响铃→贪睡」 | 实现分支、第二次贪睡、时间修订、答案校验、回执计算与重置；用可传入的时间戳检查计时；向 B 提供各阶段样例 | 交 B 同一模块入口，交 A 规则验证结果。相同初态和事件得到相同结果，错误输入不推进，原合同可在回执中还原 |
| **D 用户验证、海报与路演** · `pitch/` | 找 3–5 位目标用户问最近一次关掉闹钟又睡回去的经历；整理匿名原话；画一张双合同分支草图 | 初版出来后邀请两位未参与开发的人分别走两条路径，记录卡点；用 Dify 的 AMD 插件生成海报底稿，换成真实截图；准备 90 秒讲稿和备用录屏 | 给 A 海报、可复述的观察、视频和提交文案。核验海报有场景、三处机制及回执；从观众设备打开演示链接并计时彩排 |

A 维护公共契约和发布版本；B、C 各自在自己的目录提交；D 把截图需求及试玩卡点发给对应负责人。每个交付点由下游成员实际打开或调用一次，再在队内看板勾选。姓名由四人自行认领。

## 实现约定与联调

建议采用静态 HTML、CSS 和 JavaScript ES 模块。仓库根目录作为静态服务根目录，入口为 `frontend/index.html`。B 从 `../backend/contract.js` 导入 C 的规则，部署产物同时包含这两个目录。本地通过 HTTP 打开；现场以按钮模拟第二天和五分钟后。应用内签名与计时可在一次页面会话内完成。浏览器刷新后回到签约页，注明这是新一轮演示。

| B 调用 C 的约定 | 最少字段或规则 |
| --- | --- |
| 初始状态与合同 | C 提供 `initialState()` 与 `transition(state, event, nowMs)`。签约事件含 `time`（24 小时制 HH:mm）、`reason`、`policy`（`one_snooze` 或 `amend_first`） |
| 事件 | `SIGN` 签约、`RING` 模拟响铃、`SNOOZE` 请求贪睡、`AMEND(time)` 确认改时、`REQUEST_CLOSE` 申请关闭、`ANSWER(value)` 提交答案、`CONFIRM_CLOSE` 完成、`RESET` 清空。演示静音由 B 管理 |
| 界面读取 | `phase` 依次可为签约、待响、响铃、修订、延后、答题、验收、完成；另取原合同、当前约定时间、贪睡次数、校验提示和回执数据。B 根据状态绘制，C 决定能否前进 |
| 计时与声音 | B 传同一单调时钟的毫秒数。C 累计答题阶段为任务耗时、修订及验收阶段为手续耗时，排除模拟睡眠。B 在响铃、修订、答题、验收阶段维持同一声音实例；延后、完成、重置立即停响 |

首次联调固定使用 07:00、“八点接室友”、17＋26＝43。两人各跑一种条款后交换，逐项对比是否须修订、响铃状态和回执。若时间紧，先删扩展题库、颜色干扰题和装饰动效；保住两条分支、三处反向机制、回执和可访问链接。

## 最终验收与现场脚本

- [ ] **宽松合同**：07:00 第一次直接延到 07:05；模拟再响，第二次进入修订；仍可经关闭认证结束。
- [ ] **严格合同**：点贪睡看到签约时的原话；错误目标时间可改；正确修订后停止响铃，回执保留原约定。另试 23:58 加五分钟得到次日 00:03。
- [ ] **直接关闭**：经过意向登记、滑块、验收。答错重试成功，选择继续监督后可以完成，最终声音停止。清醒耗时和手续耗时与操作大致相符。
- [ ] **现场可靠性**：演示静音不跳阶段；重置清除上轮合同、声音和计时。新窗口可访问线上版本；本地副本及视频已在展示电脑验证。
- [ ] **调研与展台**：D 将首轮访谈扩展为全队累计 10–20 位同学的快速调研，记录实际人数、一句匿名原话和一处因此调整的设计。90 秒操作演示后，留出时间在 3–5 分钟展台时段说明发现并回答问题。
- [ ] **海报**：D 按[仓库提交清单](TEAM_PLAN.md)与现场指引保留 AMD 未编辑原图及 Gallery 生成证明截图，提供两个公开链接；保留生成的主视觉，仅轻度编辑排版。最终图设为 Devpost Project image，PDF 上传 File Upload。
- [ ] **赛道交付**：A 与 D 核对四位成员已加入 Devpost，项目页写明分工、功能取舍及工具披露；公开演示和 Apache-2.0 源码链接可用。提交后保存确认。

**90 秒演示**：D 用 10 秒解释赴约场景；评委用 15 秒签下严格条款并留下理由；B 在旁边准备宽松合同。两人同按「再睡五分钟」，花 20 秒看清分支与原话。评委修订合同、模拟再响、完成关闭，约 30 秒。最后 15 秒对照回执中的原时间、修订时间、答题与手续用时，并指出哪个步骤帮助清醒，哪个步骤只是合同多加的负担。
