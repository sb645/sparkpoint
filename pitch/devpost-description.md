## Project Title

昨晚的我有限公司 | Last Night Me, Inc. — 起床合同闹钟

## Short Summary（一句话）

一个由"昨晚的你"签合同定规则、"今早的你"必须照约执行的闹钟：让清醒时的你，提前替迷糊时的你做决定。

## Full Description

### 问题

有早八课的大学生不缺闹钟——缺的是"闹钟响了却没有顺手关掉接着睡"的自制力。睡眠研究称其为**睡眠惯性（sleep inertia）**：刚醒来的十几分钟里，人的判断力与反应速度显著下降。行为经济学则称之为**时间不一致（time inconsistency）**：计划时我们选择长远利益，当下却选择再睡五分钟。

我们在现场调研了 __ 位同学：__% 承认这学期关掉闹钟后又睡了回去。一位同学的原话："________。"

### 目标用户

有早课、早八或必须早起赴约，但经常"关掉闹钟又睡回去"的大学生。

### 解决方案（含取舍）

《昨晚的我有限公司》把起床变成一份合同：**甲方是昨晚的你，乙方是今早的你，系统是中立的执行人**。睡前签下起床时间、一句起床理由，并选择宽松条款（允许直接贪睡一次）或严格条款（贪睡必须走修订手续）。早上闹钟响起，一切阻力都来自你自己签的条款。

**刻意设计的抓狂机制（本作品是 Reverse UX 赛道作品）**：

1. **关闭按钮只登记"意向"** —— 违反"按钮应兑现标签"原则。睡眠惯性下的一次点击，不应有权力撕毁合同。
2. **用 0–100 滑块提交精确算术答案** —— 违反"控件应匹配任务"原则。能精确拖到 43，本身就证明你醒了。
3. **清醒认证通过后仍需二次验收**，且完成按钮放在视觉次要位置 —— 违反"完成后应轻松离开"原则。退出成本让"关掉再睡"不再顺手。
4. **严格合同的修订手续** —— 想贪睡，先面对昨晚自己写下的原话，再亲手把时间改掉。过去的授权约束现在的选择。

**有分寸的严格**：任何时刻都有路可走——答错可无限重试、已完成的步骤全部保留、"不可抗力"按钮随时可用（生病/急事直接停响，回执如实记录豁免）。

**功能取舍（48 小时 MVP 边界）**：真实跨夜闹钟用"模拟第二天"按钮代替（如实说明，正式产品需做成手机原生 App）；不做登录注册、多设备同步、数据库；不做与 Alarmy 重复的通用跳舞/深蹲任务。

### 原型核心功能

- **合同状态机**：确定性纯 JavaScript 状态机（`initialState()` / `transition()`），同一初态和事件序列永远得到同一结果，任何状态不卡死。
- **个性化清醒认证**：签约时做 5 次毫秒级反应测试记下"你自己的基线"；早上在模糊晃动的画面（模拟睡眠惯性）中重测，达到**昨晚的自己**的水平才算清醒。反应越快，画面越清晰。这是与"给所有人出一样的题"的同类产品最本质的区别。
- **AI 甲方**：修订页可写一句借口，AI 扮演昨晚的你、引用你自己的原话反驳。AI 只说话、不参与流程判定；8 秒超时即兜底显示原话，演示永不卡死。
- **真实数据履约报告**：原定时间、最终时间、贪睡次数、清醒耗时、手续耗时、昨晚与今早反应速度对比——全部来自本次真实操作，由甲方乙方共同署名："您已成功证明：现在的你，配得上昨晚的你。"
- **「查看设计逻辑」开关**：打开后每个机制旁出现说明卡，写明它违反了哪条 UX 原则、为什么这样设计。

### 工具与开源披露

- 前端：原生 HTML / CSS / JavaScript ES 模块，无框架、无构建步骤。
- 部署：Vercel（静态托管 + Serverless Function）。
- AI 甲方：调用主办方赞助的 AIHubMix / Tokener.ai（每队 US$12 额度）；密钥仅存于服务端环境变量。
- 海报主视觉：AMD Creative Factory（OneclickAMD）生成，仅做轻度排版编辑。
- 开发过程使用 AI 编程助手辅助编码与文档。
- 许可证：Apache-2.0。
